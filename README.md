# a9route —— 跑图视频 → 路线

把一段《狂野飙车9》的比赛录像喂进来，**每个整百分点截一张图 + 判断那一刻在做什么**，
生成一条可以直接粘贴的百分比路线（`1,31,2,N:0:2:750,4,360,…`）。

**这个项目不连手机。** 一次都不需要 adb、不需要标定、不需要设备 —— 只要录像文件。

识别**不是靠调阈值猜的**：刹车/氮气、选路（岔路口有几个、选了第几个）都由
**训练好的 YOLOv8 模型**判（`models/*.onnx`，**模型就在仓库里**，clone 下来就能跑）；
「路程 NN%」由 PaddleOCR 读；`360 / 漂移 / 双击氮气` 由**信号形状规则**推出。

---

## clone 之后怎么跑起来（约 5 分钟）

```powershell
git clone git@github.com:LucasDr06/a9route.git
cd a9route

# ① 环境：Python ≥3.10；依赖只有 numpy / opencv / flask（+ 推理用的 onnxruntime）
python -m venv .venv ; .\.venv\Scripts\activate
pip install -e ".[model]"          # 运行时（含 onnxruntime）
# 想让它读「路程 NN%」还得装 OCR（几百 MB，首次会下模型）：
pip install -e ".[ocr,model]"

# ② 自检：不需要设备、不需要网络、不需要录像
a9route test all                   # 全量离线回归（当前 641 项，约 10 秒）
a9route train doctor               # 看环境/模型/数据集各自的状态
python tools/clean_env_check.py    # 确认「只装了运行依赖」的环境也能全绿（见下面「测试」）

# ③ 放一段录像进去，然后分析
copy 你的录像.mp4 output\
a9route analyze output\你的录像.mp4      # 产物在 worktmp/analysis/<视频名>/
a9route serve                            # 或双击 serve.cmd -> http://127.0.0.1:8790/
```

**仓库里有什么、没有什么**（决定了你要自己准备什么）：

| | 状态 |
|---|---|
| 代码 + 文档 + 测试 | ✓ 全在 |
| **两个训练好的模型** `models/keys.onnx` / `choice.onnx`（~23 MB） | ✓ 在（所以 clone 下来直接能分析） |
| **跑图录像** | ✗ 自己录（`*.mp4` 不入库；放 `output/` 或设 `A9ROUTE_VIDEO_DIR`） |
| **训练数据集** `datasets/`（含人工复核过的标注） | ✗ 几百 MB，不入库 —— 要自己 `train build` + 标注，见 `TRAINING.md` |
| 训练产物 `models/runs/`、预训练权重 `models/weights/` | ✗ 不入库（`train fetch` 能重下 yolov8n.pt） |
| 你调好的参数 `config.json` | ✗ 本机私有 —— **但不需要它**：内置默认值就是调好的那套（`config.example.json` 只是格式示例） |

> **环境要求**（硬性）：录像必须 **1280×720**、画面里有**完整的比赛 HUD**
> （左上角「路程 NN%」）。所有框都是在这个分辨率上量的。

### 仓库里那两个模型是什么

| | `models/keys.onnx` | `models/choice.onnx` |
|---|---|---|
| 判什么 | 刹车 / 氮气**按键有没有按下** | 路标图标 + **哪个被选中** |
| 类别 | `brake_pressed` / `nitro_pressed` | `choice_icon` / `choice_selected` |
| 训练数据 | `datasets/keys`（1200 帧，人工复核 572） | `datasets/choice`（1200 帧，**全部人工复核**） |
| mAP50 | **0.9748** | **0.9843**（`box_map` 0.851） |
| 默认 conf | `0.40` | `0.30` |
| 选路三个答案同时都对 | — | **0.990**（同一份数据上启发式是 0.9425） |
| 训练时间 | 2026-09-15 16:06 | 2026-09-15 18:21 |

同目录下的 `keys.json` / `choice.json` 是**模型清单**（类序 / imgsz / conf / 指标 / 训练时间），
`train use` 和运行时都会**核对类别顺序** —— 把选路模型切给按键会直接拒绝，不会静默出错。

## 为什么要单独做一个项目

这套东西原来长在 `asphalt9auto`（手机自动化：adb / 标定 / 手柄 / Web 控制台）里，
但视频分析这条线**跟设备没关系**。分开的直接好处是**调参不用再跑整个项目**：

| | 原来 | 现在 |
|---|---|---|
| 改一个阈值 | 改 `a9auto/race/cues.py` 里的常量 | 网页「参数」弹窗拖滑块，或 `config.json` / `--set` / 环境变量 |
| 验证改动 | 跑整个项目的全量回归 | `a9route test all`（641 项，约 10 秒，纯离线） |

搬迁时判据是逐字搬的，之后这一轮把**识别整体换成了模型**（按键 + 选路两条线），
并把它们做得**可训练、可评估、可标注** —— 见下面「怎么训自己的模型」。

```powershell
                                # 也可以直接双击根目录的 serve.cmd（= python main.py）
                                # ⚠️ 服务就跑在**这个终端窗口的进程里**，窗口别关；Ctrl+C 停
                                # 页面右上「参数」= **可编辑的判据参数**（滑块/数字框，
                                # 保存即写进 config.json，下一次分析生效）

# ③ 只想对齐时间、自己填操作

& $py -m a9route train eval --name keys --weights models\keys.onnx   # 逐帧评估（并排打启发式对照）
& $py -m a9route train export --name keys        # 导出 ONNX + 写模型清单
& $py -m a9route train models                    # 看有哪些模型
& $py -m a9route train use keys                  # 换模型（**核对类别顺序**，切错直接拒绝）

# ⑦ **选路**也用 YOLO（另一套类别 / 另一个数据集 / 另一个界面）
& $py -m a9route train choice-build --source keys   # 从按键数据集分类出来（硬链接，不占空间）
& $py -m a9route train choice-stats                 # 看分布
                                #   标定：http://127.0.0.1:8790/choice（三个选择题）
& $py -m a9route train run --name choice            # 训练
& $py -m a9route train export --name choice         # -> models/choice.onnx
& $py -m a9route train use choice                   # 切运行时后端

# ⑧ OCR 模型缓存（读不到时会读不出「路程 NN%」，路线就空了）
& $py -m a9route ocr status                      # 看能不能读到
& $py -m a9route ocr cache                       # 抄一份到工作区（做一次即可）
```

> **两个环境**（这是本机的情况，别人 clone 后按上面「clone 之后怎么跑」装即可）：
> * `alphash9auto`（Python 3.12）：**运行 + 标注 + 评估** —— numpy / opencv / flask /
>   paddleocr / **onnxruntime**（不装 torch）；
> * `ai_joy`（Python 3.9）：**训练/导出** —— torch 2.8.0+cu128 + ultralytics（RTX 50 系必须 cu128）。
>
> 依赖清单见 `pyproject.toml`（`pip install -e ".[model]"` / `".[ocr]"` / `".[train]"`）。
> `python main.py` 与 `python -m a9route` 等价；**不带参数就是起 Web 窗口**。
>
> **判定全部来自模型**：按键 `key_backend=auto` → `models/keys.onnx`，
> 选路 `choice_backend=auto` → `models/choice.onnx`。
> ⚠️ `auto` **不静默退回启发式**：模型文件不在就**报错**（这次分析无效，并告诉你
> 怎么修），因为"看起来正常、其实是像素判据"的路线比报错更坏。
> 想用启发式请**显式**设 `vision.key_backend=heuristic`（只用于调试/预标注）。
> 「路程 NN%」用 PaddleOCR；`360 / 漂移 / 双击氮气` 由**信号形状规则**推出
> （`core/intent.py`，模型给的按键信号 + 用户定的规则）。
>
> **两个训好的模型（~23 MB）就在仓库里** —— clone 下来直接能跑 `analyze`；
> 数据集（几百 MB、含人工标注）和训练产物（`models/runs/`，66 MB）不入库，
> 见 `models/README.md`。**不用配 `config.json`**：内置默认值就是调好的那一套
> （实测：删掉 `config.json` 之后同一段视频跑出来的路线**一字不差**）。

## 参数在哪调（**这是本项目存在的意义**）

所有可调项集中在 `config.json`（**没有这个文件就全用内置默认值 —— 这是推荐状态**）。
优先级：**环境变量 > `config.json` > 内置默认值**。

> **内置默认值就是调好的那一套**（`choice_conf=0.30`、`choice_idle_hold=8`……），
> 所以 clone 下来**什么都不用配**。`config.json` 只在你要偏离默认值时才需要 ——
> 仓库里的 `config.example.json` 是**格式示例**（顺便演示几个常见改法：抽帧更密、
> 并行更高、选路带挪位置），`copy config.example.json config.json` 之后按需改。
> ⚠️ 在里面写**绝对路径**（比如 `vision.key_model`）会让配置不能跨机器/跨目录搬 ——
> 一般留空就够了，空 = 用 `models/keys.onnx`。

### ① 网页里拖滑块（推荐，改完立刻看得到中文说明）

```
a9route serve   ->  页面右上「参数」
```

弹窗里是 **29 个可编辑项**，按五组排（选路 / 按键 / 信号形状 / 扫描节奏 / 标定位置框），
每一项都是**滑块 + 数字输入框**（改完当场显示"已改"，右边有「默认」一键还原）。
几个关键点：

* **只让你填合理的值**：每项都有 `min/max/step`，**后端还会再校验一遍**
  （前端不是闸门）——`choice_idle_hold = -1` 这种值会被 **400 拒绝**，
  不会先写进文件再让行为变得莫名其妙；
* **哪一项当前到底生效，页面直接告诉你**：`vision.choice_param2`（HoughCircles 灵敏度）
  现在**不生效**，因为选路跑的是模型 —— 这类"调了没反应"的坑，页面会标注
  「当前后端 = 模型，这一项不生效」；
* 保存是**整体成功或整体失败**，写进 `config.json`，**下一次分析生效**（正在跑的不受影响）；
* 与默认值相同的键会被**从文件里剔掉**，所以 `config.json` 里只留你真正改过的东西。

### ② 命令行 / 配置文件

```powershell
& $py -m a9route config list            # 看当前生效的全部参数
& $py -m a9route config list --changed  # 只看被我改过的
& $py -m a9route config set scan__choice_idle_hold=12       # 写入 config.json
& $py -m a9route config set scan__every=0.2 scan__workers=4
& $py -m a9route config reset scan__choice_idle_hold        # 单个键恢复默认
& $py -m a9route config reset                                # 全部恢复默认

# 只影响这一次运行（不写盘）——调参时最常用
& $py -m a9route analyze 录像.mp4 --set scan__choice_idle_hold=12 --verbose
# 环境变量（临时/CI 用）
$env:A9ROUTE_scan__choice_idle_hold = "12"
```

### 四段参数（网页那张表就是照它分组的）

| 段 | 管什么 | 里面最可能要动的 |
|---|---|---|
| `scan` | 抽样节奏与判定闸门 | `every`（抽帧间隔）、`max_seconds`、`workers`、`hold`/`hold_brake`（分通道去抖）、`choice_min_hold`（选路闪烁闸）、**`choice_idle_hold`（选路结束闸）**、`choice_cross_tol`（选路交叉校验）、`icon_every` |
| `vision` | **模型开关 + 置信度** + （只给启发式用的）阈值 | `key_backend` / `choice_backend`（`auto`/`onnx`/`ultralytics`/`heuristic`）、`key_conf`、`key_iou`、`choice_conf`、`choice_iou`、`choice_min_options`/`choice_max_options`；启发式那一支才用到的 `nitro_red_thr` / `brake_ring_thr` / `brake_white_thr` / `choice_param2` / `choice_blue_ratio` |
| `hud` | 比赛内读数框 | `progress_box`（**路程 NN%，路线百分比只认它**）、`rank_box`、`touchdrive_box`、`choice_band`（选路带，**模型出的路标只在带内才收**） |
| `intent` | 信号形状 → 操作目的 | `tap_360_gap`（成对脉冲判 360）、`drift_min`（按住 vs 短脉冲）、`nitro_gap`、`nitro_hold` |

> 训练那一侧的参数（数据集路径、`imgsz`、`epochs`、预标注来源…）**不在 `config.json` 里**，
> 它们是 `train` 子命令的参数，见 `TRAINING.md`。

**`scan.choice_idle_hold` 是这一轮新加的关键旋钮**：连续多少个采样点没有路标
就把"这一段选路"关掉（默认 8，≈0.53 秒）。调小 → 一个岔路口会被拆成两段（多报）；
调大 → 相邻两个岔路口会被并成一段（少报）。它计数的是**原始采样点**，不受 `icon_every` 影响。

**调参不要凭感觉。** 每个默认值后面都写着实测数据（`config.py` 里有完整注释），例如：

* 按键模型 `key_conf = 0.40`、选路模型 `choice_conf = 0.30` —— 都是
  `train eval` 扫出来的最佳档，不是拍的；
* 选路的闪烁闸 `choice_min_hold = 4`：不加它时，10 秒视频能报出 16 次选路（实测）；
* 启发式那一支（只在 `backend=heuristic` 时用）：氮气键 `红占比 > 0.15`
  （实测"按下 0.36 / 没按 0.09"）、刹车键 `圈内白度 − 圈外参照白度 > 0.35`
  （实测 0.37 / 0.11）—— 半透明图标**必须用相对量**，绝对值会被赛道明暗带走。

### 位置框长什么样

两个按键框是**整个圆**：`brake_key_box=(137,497,110,110)`、
`nitro_key_box=(1033,497,110,110)`（圆心 (200,552)/(1080,552) 半径 ≈50，
关于屏幕中线 x=640 完全对称）；选路带 `hud.choice_band` 是屏幕上方那条。

> ⚠️ 这两个按键框**现在只影响标注页怎么裁图/画框**（判定已经交给模型了）。
> 改完记得跑 `a9route train audit` 看数据集里的标注还对不对得上。
> 选路带 `choice_band` 则是**运行时真闸门**（带宽 ±24 px 之外的路标不算）。

### 换分辨率时怎么重量框

1. 从录像里抽一张比赛帧（`--verbose` 跑一次，或直接看 `worktmp/analysis/*/shots/` 里的图）；
2. 把候选框画回帧上存成 PNG 看一眼（**必须画出来核对** —— 原来那两个按键框
   就是这么发现"只压到图标左上弧"的 ✗）；
3. `config set vision__nitro_key_box=x,y,w,h`（逗号分隔，会按 `list[int]` 解析）；
4. `a9route test video` 复跑 —— 里面有真帧样本回归，能立刻告诉你框对不对。

## 输出长什么样

`analyze` 的产物（下面的真实样例来自 `output\跑图转路线测试.mp4`，21 个操作）：

```
worktmp/analysis/<视频名>/
├── route.txt                  # 完整路线：正文是扁平逗号流，上面是逐条判据注释
└── shots/
    ├── 001pct_t012.50s.png    # 每个整百分点一张（文件名带百分比与时刻）
    └── ...
```

`route.txt` 长这样（下面全部是**原样抄的真实产物**，注释是**真的**——
每条操作都写了它凭什么这么判）：

```
# 由跑图视频**自动推断**的路线（操作是判据猜的，请核对后使用）
# 精细扫描判出 21 个操作：360 1 / 漂移 4 / 打断氮气 1 / 氮气 8 / 选路 7
#   —— 精细扫描只出时间戳，百分比是事后按「时间->百分比」对齐的；
#      氮气写法里的间隔是**逐帧量出来的实测值**（不是估算）✓
# 判据：刹车键**成对脉冲(间隔 <0.3s)=360**、**独立短脉冲=打断氮气**、按住=漂移；
#       氮气键=正在点氮气（多次连点每百分比最多取两次 + 实测间隔）；
#       选路=上方圆形路标（**按「选路段」取**：持续没路标=这一段结束；段内没变取第一次、
#       只有选中变了取最后一次、选项数变了立刻开新段）。
# ⚠️ 上面这些都来自**模型**（按键=onnx:keys.onnx / 选路=onnx:choice.onnx）＋信号形状规则；
#    只有「关自动驾驶 S:2000」例外 —— 它是 **OCR 文字判据**（读到「TOUCHDRIVE」），
#    用户口径：touchdrive 就用 OCR 识别（不训模型）。详见下面单独那一段。
# 同一个百分比上的多个操作用 | 连起来（= 同时执行）。
# 用法：核对 -> python -m a9route check --text "<上面那一行>"

5,31,7,360,9,N:0:2:166,14,D:1064,19,N:100:1:100,21,N:100:1:100,33,D:4365,42,21,43,N:0:2:167,49,D:230,50,21,56,22,58,N:100:1:100,59,N:100:1:100,68,31,69,21,74,D:2597,79,N:0:2:167,83,21|D:2698,90,N:0:2:167

# ---- 精细扫描判出的操作（时刻 + 判据）----
```

注意头几行**是算出来的、不是写死的**：`<0.3s` 来自当前生效的 `intent.tap_360_gap`，
`onnx:keys.onnx` 来自当前生效的后端 —— 你 `train use` 换了模型、
或把 `tap_360_gap` 调成 0.4，路线文件里这几行会跟着变（以前这里是写死的常量，
输出会一本正经地写错自己，已修）。

**路线格式**（与手上那份现成脚本 1:1 兼容，`a9route/core/route.py` 是唯一事实来源）：

| 写法 | 含义 |
|---|---|
| `NN`（两位数字） | 选路：前一位=图标数量、后一位=选第几个（从左数，1 起）。`31` = 3 选 1 |
| `N:延时:次数:间隔` | 点氮气。`N:0:2:750` 完美氮气；`N:500:10:100` 快速连点 |
| `D:毫秒` | 漂移 |
| `S:毫秒` | 关自动驾驶（之后自动打开，不建议用）|
| `360` | 360 操作 |
| `A\|B` | 同时执行：`83,21\|D:2698` |

解析器会主动挑错：中文标点（`，：｜`）、缺逗号、选路越界、氮气 0 次、
连点却把间隔写成 0、漂移 0ms、百分比越界，都带行号报错；
警告只留两条：同百分比出现多次、**氮气落在漂移窗口内**（点氮气会取消漂移）。

## 三条判据线（算法骨架）

> 判定**全部来自模型**（2026-09-15 起）。下面第 3 条里"什么形状算 360 / 漂移"是**用户定的规则**，
> 但"那一刻刹车有没有被按下"始终是**模型**说了算 —— 没有一处再回到像素阈值。

1. **粗扫**（`vision/video.py::extract_per_percent`）：按 `scan.every`（默认 0.25s）
   抽帧，逐帧喂给两个模型 + PaddleOCR 读「路程 NN%」→ 每个整百分点**存一张 PNG**，
   并把该百分点附近的检测汇总成一个操作（单帧会闪，窗口汇总才稳）。
   粗扫**不产路线**：它只负责百分比与截图。
2. **精细扫描**（`scan_fine`，和粗扫**并行**、各自一路解码、共用同一个检测器）：
   逐帧只看两个按键（刹车 / 氮气）+ 每 `scan.icon_every` 帧看一次选路路标，
   **只产时间戳**。⚠️ 这里必须把**同一个模型后端**注入进去 ——
   历史上有过"粗扫偷偷用 HoughCircles，把模型判出的选路否掉"的 bug，
   现在有专门的回归（反例探针里 HoughCircles 调用数必须是 0）。
3. **判目的**（`core/intent.py`，输入是模型的按键/路标时间线）：
   * 刹车**成对脉冲**（间隔 < `tap_360_gap`，默认 0.30s）= **360**；
   * 刹车**独立短脉冲** = **打断氮气**（很短的 `D:`）；
   * 刹车**按住** ≥ `drift_min`（默认 0.30s）= **漂移**；短于它 = 打断氮气；
   * 氮气**多次快速点击** = 每百分比最多取两次 + **实测间隔**
     （`N:0:2:167` 里的 167 是逐帧量出来的，不是估的）；
   * **选路**：按「段」判，规则如下（用户 2026-09-15 定的四句话）：
     1. 持续没有检测到路标 → 进入**选路结束**状态；
     2. 在"结束"状态下第一次检测到路标 → **开始一段**；
     3. 段内**同一组选项一直不变** → 取**第一次**检测到的（几个选项 + 选第几个）；
     4. 只有**被选中的那个变了**（选项个数没变）→ 取**最后一次改变**；
        而**选项个数变了** → 立刻结束这一段、**另起一段**（说明是新的岔路口了）。

   最后用「时间 → 百分比」的插值关系把时间戳落回百分比（`attach_events`）。

> 模型出来的路标**只在 `hud.choice_band ± 24 px` 带内才收**（带区闸）——
> 模型有时会在带下方那些圆形 UI 上误触发，这一闸是实测加的。
> 精细扫描判出的选路还会跟粗扫**交叉校验**（`scan.choice_cross_tol`），
> 对不上就丢掉并**打印丢了什么**，不静默。

> 为什么第 2 步不直接产百分比：路线脚本的精细度只有 **100 次**，
> 同一段里可能连做好几个动作，光有"这个百分点按键亮着"分不出**这次按键是为了什么**。
> 这是用户 2026-09-13 明确给的规则。

**唯一保留的 OCR 判定**：`S:2000`（关自动驾驶）—— 用户明确要求"touchdrive 还是用 OCR 识别"，
路线文件里会标明这一条来自 OCR 而不是模型。

三条判据各自的**实测数据、走过的死路、为什么不用模板匹配/圆检测**：见 `NOTES.md`。

## 已知限制（老实说）

识别换成了模型，但**定位没变**：视频里看不到按键真值，模型也会有错，
所以这是「**自动生成草稿 + 人工核对**」，Web 窗口会把每个百分点的判据一并摊开。

### 模型 vs 启发式：同一段视频的实测

同一段 `output\跑图转路线测试.mp4`、同一套代码，只换后端：

| | 精细扫描判出的操作 | 其中氮气 | 路线条目 |
|---|---|---|---|
| **模型**（默认） | 21 | **8** | 21 |
| 启发式（`--set vision__key_backend=heuristic …`） | 48 | **25** | 40 |

原来交接文档里记的两条毛病，都是**启发式**那一支的毛病：

* **"氮气偏多"**：启发式 25 条 vs 模型 8 条。原因当时也查清了 —— 项目里原来有**两套**
  启发式口径，而真正产出路线的 `scan_fine()` 用的是**被 NOTES §1 否掉的那套**
  （把"圈内白度"这个对氮气**没信号**的通道也并了进来）。
* **"选路条目比实际多"**：这一条分两步修好的，**别把功劳都记在模型头上**：
  ① 用户口径的**分段状态机**（`core/intent.py`）先把"一个岔路口只留一个结论"做到 ——
  这段视频从 12 条降到 7 条，**两个后端都一样**（状态机与后端无关）；
  ② 选路**模型**接着把"答案对不对"提上去 —— `train eval` 上「三个答案同时都对」
  **0.9425 → 0.990**，"有没有岔路口"的错法 **19 处 → 1 处**。

> ⚠️ 但请注意：**上面的"正确答案"仍然是我用数据集的标注算出来的**，不是你在真机上核对过的。
> 8 条氮气是不是真的对，得你拿着录像核对 —— 工具只能保证"每条都写了它是怎么判出来的"。

### 还没解决 / 要注意的

* **只在 1280×720 的录像上验证过**。所有框（两个按键圆、选路带、HUD）都是这个分辨率量的；
  换分辨率必须重量框，见上面「换分辨率时怎么重量框」。
* **训练数据的覆盖面就是它的天花板**：`datasets/keys` 1200 帧（复核过 572 帧）、
  `datasets/choice` 1200 帧（全部复核）。**换赛道、换天空、换 HUD 皮肤**都可能掉点，
  而掉点不会报错 —— 会安静地给出错路线。修法是**再录一段、`train build` 加进去重训**。
* **选路带区闸是个取舍**：模型在带下方那些圆形 UI 上会误触发，所以只收
  `hud.choice_band ± 24 px` 内的检测。代价是**带外的真路标也会被丢弃**。
* **`choice_idle_hold`（选路结束闸）没有万能值**：两个岔路口挨得很近时，
  默认 8（≈0.53s）可能把它们并成一段。这就是它做成可调滑块的原因 —— 见「参数在哪调」。
* **`S:2000`（关自动驾驶）仍然靠 OCR 文字**（用户口径："touchdrive 就用 OCR 识别"）。
  它是路线里**唯一**不来自模型的操作，路线文件里单独标出来了。
* **OCR 起不来 → 路线是空的**：读不到「路程 NN%」时，每个百分点都进不了。

  > ⚠️ **2026-09-15 补**：这条曾经**看起来像 bug** —— 用户报"识别路线识别不到任何操作"，
  > 查下去真凶是 **`~/.paddlex` 在工作区外、受限环境读不到 OCR 模型** →
  > 路线必然是空的，**跟检测毫无关系** ✗✗。现在：① `a9route ocr cache` 把模型
  > **抄一份到工作区**（约 21 MB，做一次即可）；② 一张图都没扫到时 `analyze` 会
  > **当错误报出来**（CLI 退出码非 0、界面弹红框 + 能照做的命令），
  > 而不是给一条空路线让人以为"这视频没操作"。见 NOTES §10.17。
* **模板匹配已经被判定走不通**（图标是半透明叠加，模板主要在匹配背景），别再去调模板；
  同理，圆检测（HoughCircles）那一支现在只是**预标注/对照**用的。
